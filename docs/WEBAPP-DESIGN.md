# Web アプリ化の設計メモ

仕様書 `GAS-PORTING-SPEC.md` §6 は「クリック入力はサイドバー（HtmlService）で代替する」
と確定方針にしていた。**2026-09-03 に利用者の判断で「シフト表ごと Web アプリ化」へ変更**した。
この文書はその経緯と、変更に伴う割り切りを残すためのもの。

---

## 決定

| | 旧（仕様書 §6） | 新 |
|---|---|---|
| 入力の場所 | スプレッドシートのサイドバー | Web アプリ（`doGet`）の独自グリッド |
| 対象セルの決め方 | 押した瞬間の `getActiveRange()` | 画面で押されたセルを自分で覚える |
| 表の描画 | Sheets がやる | **自分で描く** |

サイドバー（`Sidebar.gs` / `Sidebar.html`）は消さずに残す。
スプレッドシートを直接開いて使う人にはそちらの方が速いため。骨組みのまま。

### 反対意見も記録しておく

実装前に「別立ての Web アプリは勧めない」と伝えた。理由は3つ。

1. シフト表は Sheets 上で読んで直すもの。HTML に描き直すと、印刷・共有・履歴・
   同時編集など **Sheets が既にうまくやっていることを作り直す**ことになる
2. Web アプリからは `getActiveRange()` が使えないので、
   サイドバーの「選択してからボタン」という設計が丸ごと成立しない
3. 「シートごとに生成」は `SheetBuilder` のメニューで達成済みで、Web アプリでなくても足りる

利用者はそのうえで Web アプリ化を選んだ。**判断は利用者のもの**なので、この方針で進める。
上の3点は「作らない理由」ではなく「作るときに気をつける点」として残す。

## 設計

### 読み書きの経路

```
ブラウザ ──google.script.run──▶ WebApp.gs ──▶ Layout.resolveLayout()
                                     │
                                     ├─ apiLoadGrid   … 表示ブロックを1回だけ読む
                                     └─ apiSaveCells  … 編集の外接矩形を1回だけ書く
```

- **読み**: `A1` から `AN{過不足行}` までを `getValues` / `getDisplayValues` /
  `getFormulas` の3回で取る。以降はメモリ上で組み立てる（§8.3-3）
- **書き**: 編集が散らばっていても、外接矩形を1回読んで1回書く。
  矩形の中の数式セルは数式のまま書き戻す（`setValues` に `"=..."` を渡すと数式になる）

### サーバ側で必ず検証する

`editRejectReason_()` が、行・列が書き込んでよい範囲かを見る。
**画面側の制限だけに頼らない。** 画面のバグや細工したリクエストで
集計行や日付行に書き込まれると、表が黙って壊れる。

書き込みを許すのは次の行だけ。

| 行 | 用途 |
|---|---|
| `gridTop`〜`gridBottom` | スタッフの入力欄 |
| `doctorTop`〜`doctorBottom` | 医師名欄 |
| `doctorBottom + 1` | 自由行（発注担当など） |
| `noteRow` | 備考行 |

列は `firstCol`〜`lastCol`（B〜AF）のみ。数式セルは種別を問わず拒否し、
**黙って無視せず拒否した旨を画面へ返す**。

### いまできること / できないこと

| | 状態 |
|---|---|
| シートの一覧と切り替え | できる（Layout が解決できるシートだけ候補に出す） |
| グリッドの表示（日付・曜日・土日祝・月外・医師名・備考・集計行・集計列） | できる |
| スタンプでの入力と保存 | できる |
| シフト表シートの新規作成 | できる |
| 自動作成の実行 | **できない**（配置エンジンがフェーズ3のため） |
| 変更ログへの記録 | **できない**（フェーズ5。`apiSaveCells` に TODO を置いてある） |
| PDF 出力 | **できない**（フェーズ7） |
| 背景色の塗り分け | **できない**（サイドバー側の仕様。必要なら移す） |
| 月送り | シート切り替えで代用。専用の前月/翌月ボタンは無い |

## 割り切りと既知の弱点

### 1. 同時編集に強くない ★

`apiSaveCells` は編集の外接矩形をまるごと書き戻す。読んでから書くまでのあいだに
**誰かが同じ矩形の中を直していると、その変更を上書きする**。

いまは「保存のたびに読み直す」ことで気づけるようにしてあるだけ。
複数人で同時に触る運用にするなら、セル単位の版管理か
`LockService` による直列化が要る。

### 2. 直接編集は Web アプリからは見えない

スプレッドシートを直接開いて編集された内容は、Web アプリ側で再読込するまで反映されない。
これは Sheets の同時編集と違い、画面が自動で追随しないということ。

### 3. 大きい月でも1画面に全部描く

31 日 × スタッフ 20 行程度なら問題ないが、行を大幅に増やすと描画が重くなる。
仮想スクロールは入れていない。

### 4. 印刷は Sheets 側

Web アプリの画面は印刷向けに作っていない。印刷は PDF 出力（フェーズ7）か、
スプレッドシートを直接印刷する。

## デプロイと公開範囲 ★

`appsscript.json` の既定は**もっとも狭い設定**にしてある。

```json
"webapp": { "executeAs": "USER_ACCESSING", "access": "MYSELF" }
```

- `USER_ACCESSING` … アクセスした本人の権限で動く。
  スプレッドシートを開ける人しか中身を見られない
- `MYSELF` … 開発者本人だけが開ける

**スタッフにも使わせるなら、ここを広げる判断が要る。**
広げ方は2通りあり、意味がまったく違う。

| 設定 | 起きること |
|---|---|
| `access: "ANYONE_WITH_GOOGLE"` + `executeAs: "USER_ACCESSING"` | **スプレッドシートの共有も必要**。スタッフに表そのものを渡すことになる |
| `access: "ANYONE_WITH_GOOGLE"` + `executeAs: "USER_DEPLOYING"` | スプレッドシートを共有せずに済むが、**アクセスした全員がデプロイした人の権限で書き込む**。URL を知る Google アカウントなら誰でもシフト表を書き換えられる |

後者を選ぶなら、`apiSaveCells` に「誰が押したか」の記録（`Session.getActiveUser()`）と、
編集してよい人の名簿を足すこと。**いまのコードにその守りは無い。**

## 仕様書に反映すべきこと

`GAS-PORTING-SPEC.md` §6 は「確定済みの方針: クリック入力パレットはサイドバーで代替する」
と冒頭にも書いてある。方針が変わったので、§6 を
「Web アプリを主、サイドバーを従」に書き換えるのが筋。
ただし §6.3（押せる場所の制約）と §6.4（医師名スタンプ）と §6.6（手動変更のログ）は
Web アプリでもそのまま効く要件なので、中身は流用できる。
