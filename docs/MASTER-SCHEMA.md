# マスタ項目一覧（移行用）

試作画面（`prototype/ShiftGrid.html`）で持っている項目と、いま `Config.gs` が
定義しているシート列との対応表。**移行のときはこの表を契約とする。**

- **既存** … いまの `Config.gs` にすでに列がある
- **新規** … 試作で足した。移行時にシートへ列を足す必要がある
- **要判断** … 残すか捨てるか決まっていない

> ブラウザに入力された中身そのものは、`localStorage` にしか無く外へ出ない。
> 画面の「データ書き出し」タブから JSON で取り出すこと。

| E | 固定曜日 | `fixedDow` | 曜日7個 | 既存 | 必ず出る曜日。試作は日〜土の配列 |
| F | 週勤務日数 | `weekDays` | 数 0–7 | 既存 | |

### 曜日7個の持ち方

シートの1セルに `日月火水木金土` の順で `0`/`1` を7文字並べる
（例 `0111110` ＝ 日曜と土曜以外）。列を7本に割るより移行が楽で、
`E` 列の既存の書き方（曜日名の羅列）からも機械的に変換できる。

## 移行の手順

1. 画面の**データ書き出し**タブで JSON を取り出す。
2. `Schema.gs` に上表の**新規**列を足す（`CFG_MEMBER` の J〜Q、`PATTERN_MASTER` の G、`有休管理` シート）。
3. `migrateAssignIds_()` で既存シートに社員ID を発番する（§8）。**3 より先に 4・5 を書かないこと** — キーが無いまま参照を書くと、あとから直せない。
4. JSON を各シートへ流し込む取り込み口を作る。
5. `ShiftAuto.gs` の `readMembers_()` を新しい列まで読むよう広げる。
6. `Engine.gs` が新しい制約（連続出勤上限・出られる曜日・使える記号・締め作業）を見るようにする。

**2〜4 は 5・6 と独立して進められる。** 先にシートの形とキーを確定させれば、
エンジン側の実装と並行できる。

## 8. キー設計（リレーション）

### いまの状態

試作（`prototype/ShiftGrid.html`）では **すでに id で繋いである**。

```
社員マスタ.id  ←─ 有休管理.staffId      （有休の付与・取得）
               ←─ シフト表のセルのキー   （values の 'staffId|日' ）
               ←─ 書き出し JSON の shift のキー
```

有休管理の氏名欄は `<select>` で、**表示は氏名・保持は id**。
だから氏名を直しても、旧姓から新姓に変えても、繋がりは切れない。

**シート側にはキー列が無い。** `CFG_MEMBER` は A〜I の9列で、ID を持っていない。
移行で足りないのはここ。

### 主キーの決め方

**氏名を主キーにしない。** 理由は3つ。

1. 同姓が2人いると区別できない（実物の A 列は `氏名(週4)` のような但し書き付きで、
   氏名そのものが一意である保証がない）
2. 改姓・表記ゆれ（`髙`／`高`）で過去の記録との繋がりが切れる
3. 氏名を直した瞬間に、その人の有休記録と過去のシフトが行方不明になる

代わりに **`s` + 発行時刻の36進** を主キーにする（例 `sm7f2k1x`）。
利用者には見せない列で、シートでは**非表示列**にしておく。

### 列は挿入せず末尾に足す

`CFG_MEMBER` の列番号は `readMembers_()` が直接参照している。
A〜I の途中に ID を挿すと、**既存のシートすべてで列がずれる**。
Q 列（末尾）に足して非表示にすること。`COL_ID: 17` を `Config.gs` に追加する。

### ID が空のときの移行

既存シートには ID が無いので、初回だけ **氏名で突き合わせて ID を発番する**
処理が要る（`migrateAssignIds_()`）。

1. 社員マスタの Q 列が空の行に ID を発番する
2. 有休管理の氏名から、同名の社員を探して社員ID列を埋める
3. 同名が2人以上いたら**止めて一覧を出す**。勝手にどちらかへ寄せない

一度発番したら、以降は氏名を自由に直してよい。

### 整合性の検査

繋がりが切れうるのは **社員を削除したとき**だけ。試作では有休管理の画面に
出るようにした（`showLeaveIntegrity()`）。

- 参照先が消えた有休行 → 氏名欄に `⚠ 参照先なし（<id>）` と出る。黙って空欄にしない
- 有休行が無い社員 → 件数を出す。社員を足したときは有休行も同時に作る

**そもそも削除しないのが正しい。** 退職は在籍終了（P 列）に年月を入れる。
そうすればその月の表には出ず、過去の月を開けば従来どおり出る。

### 医師・シフトパターン・備考

これらも `id` を持っているが、**いまは誰からも参照されていない**
（シフト表には医師名・記号の文字そのものが入る）。
将来「医師ごとの必要人数」のような関係を作るときのために取ってある。
シートに ID 列を足す必要は、今のところない。

## 12. 祝日マスタ（`祝日マスタ` シート）— **シートごと新規**

元日・成人の日といった暦の祝日は**算出する**ので持たない
（固定日・ハッピーマンデー・春分秋分・振替休日・国民の休日）。
ここに入れるのは**会社として決める休み**と、**算出結果の上書き**。
同じ日に両方あれば、マスタが優先する。

| 列 | 見出し | 試作のキー | 型 | 備考 |
|---|---|---|---|---|
| A | 名称 | `name` | 文字 | |
| B | 種別 | `kind` | 下表の3つ | |
| C | 開始 | `from` | `M/D` | |
| D | 終了 | `to` | `M/D` | 年またぎ可 |
| E | 備考 | `memo` | 文字 | |

### 種別

| 種別 | 店 | 公休ノルマ | 例 |
|---|---|---|---|
| `公休加算` | 開ける | **+1 日** | 国民の祝日 |
| `休業` | **閉める**（全員休み） | **+1 日** | 三が日・年末年始 |
| `対象外` | 開ける | 数えない | 祝日だが所定休日にしない日 |

### 公休ノルマの算出

**手入力をやめ、暦から決まる値にした。**

```
公休ノルマ ＝ その月の（土曜 ＋ 日曜 ＋ 公休加算の祝日 ＋ 社内休日）の日数
```

同じ日が土日かつ祝日でも **1日として数える**（日ごとの真偽で数えるため二重計上しない）。
社員マスタの `公休 調整` は、この基準への増減。既定は 0。

検算（試作で実測）:

| 月 | ノルマ | 内訳 |
|---|---|---|
| 2026年10月 | 10 日 | 土日9 ＋ スポーツの日 |
| 2027年1月 | 12 日 | 土日9 ＋ 三が日3（1/2・1/3 は土日と重複せず） |
| 2026年5月 | 13 日 | 土日8 ＋ 憲法記念日・みどりの日・こどもの日・振替休日・(5/2土) |
| 2026年9月 | 11 日 | 土日8 ＋ 敬老の日・国民の休日・秋分の日 |

### 週勤務日数との関係

公休ノルマは**全員共通**。週4勤務の人がさらに休む分は、公休ではなく
`週勤務日数` の制約で処理する（★要確認: この理解で合っているか）。
合っていなければ `公休 調整` 列で個別に増やす。
