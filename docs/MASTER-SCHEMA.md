# マスタ項目一覧（移行用）

試作画面（`prototype/ShiftGrid.html`）で持っている項目と、いま `Config.gs` が
定義しているシート列との対応表。**移行のときはこの表を契約とする。**

- **既存** … いまの `Config.gs` にすでに列がある
- **新規** … 試作で足した。移行時にシートへ列を足す必要がある
- **要判断** … 残すか捨てるか決まっていない

> ブラウザに入力された中身そのものは、`localStorage` にしか無く外へ出ない。
> 画面の「データ書き出し」タブから JSON で取り出すこと。

---

## 1. 社員マスタ（`自動作成設定` シート）

`CFG_MEMBER`（`HDR_ROW: 4` / `FIRST_ROW: 5`）

| 列 | 見出し | 試作のキー | 型 | 区分 | 備考 |
|---|---|---|---|---|---|
| A | 氏名 | `name` | 文字 | 既存 | シフト表 A 列に出る |
| B | 区分 | `kind` | `薬剤師` / `事務員` | 既存 | `KIND` の正規値 |
| C | 休業 | — | 真偽 | **要判断** | 試作には無い。在籍期間とは別物（産休など期間内の一時離脱） |
| D | 勤務ルール | `rule` | `自動` / `手動` | 既存 | 手動は自動配置の対象外。派遣はこちら |
| E | 固定曜日 | `fixedDow` | 曜日7個 | 既存 | 必ず出る曜日。試作は日〜土の配列 |
| F | 週勤務日数 | `weekDays` | 数 0–7 | 既存 | |
| G | 月間休日数 | `monthOff` | 数 0–31 | 既存 | `RULE.NORMAL` のときだけ読む |
| H | 遅番・遅半 可否 | — | 真偽 | **要判断** | 試作では `patterns`（下）に吸収した |
| I | 備考 | `memo` | 文字 | 既存 | |
| **J** | **雇用** | `employment` | `社員` / `派遣` / `パート` | **新規** | 派遣行を区分けするのに要る。頭数には入れるが配置は手動 |
| **K** | **連続出勤上限** | `maxCons` | 数 1–14 | **新規** | 個人ごと。空欄ならルール画面の既定値 |
| **L** | **使える記号** | `patterns` | 記号を空白区切り | **新規** | シフトパターンマスタの `記号` を参照。H 列の上位互換 |
| **M** | **出られる曜日** | `availDow` | 曜日7個 | **新規** | E（固定で出る）とは別。E ⊆ M でなければ矛盾 |
| **N** | **締め作業** | `canClose` | 真偽 | **新規** | 派遣は不可。毎日1名以上いるかを検査する |
| **O** | **在籍 開始** | `from` | `yyyy-mm` | **新規** | 空欄は「ずっと前から」 |
| **P** | **在籍 終了** | `to` | `yyyy-mm` | **新規** | 空欄は「今も在籍」。**退職者を消さずに済ませるために要る** |

### 曜日7個の持ち方

シートの1セルに `日月火水木金土` の順で `0`/`1` を7文字並べる
（例 `0111110` ＝ 日曜と土曜以外）。列を7本に割るより移行が楽で、
`E` 列の既存の書き方（曜日名の羅列）からも機械的に変換できる。

## 3. シフトパターンマスタ（`シフトパターン` シート）

`PATTERN_MASTER`

| 列 | 見出し | 試作のキー | 区分 | 備考 |
|---|---|---|---|---|
| A | 記号 | `sym` | 既存 | セルに入る文字そのもの |
| B | 名称 | `label` | 既存 | |
| C | 開始 | `start` | 既存 | `hh:mm`。実物の `↑15-20` 表記はここで表す |
| D | 終了 | `end` | 既存 | |
| E | 種別 | `kind` | 既存 | `出勤` / `休み`（`備考` は旧版互換で読むだけ） |
| F | 表示順 | `order` | 既存 | パレットの並び順。1〜9 はキー割り当て |
| **G** | **出勤に数える** | `work` | **新規** | 種別が `出勤` でも頭数に入れない記号を作れるようにする。空欄なら種別に従う |

`work` を分けた理由: 研修・出張のように「出勤扱いだが薬剤師の頭数には入れたくない」
記号が要る場面がある。要らないと決まれば G 列は落として `kind === '出勤'` で判定してよい。

| 列 | 見出し | 試作のキー | 型 | 備考 |
|---|---|---|---|---|
| A | 氏名 | `staffId` | 社員マスタ参照 | 表示は氏名、内部は id |
| B | 付与日 | `grantDate` | `yyyy-mm-dd` | |
| C | 付与日数 | `grantDays` | 数 | |
| D | 取得済み | `usedDays` | 数 | |
| E | 残 | （計算） | 数 | `付与日数 − 取得済み` |

**未対応**: 付与日から2年の時効。1人が複数回の付与を持つ前提で行を分けてあるので、
時効を入れるなら「付与ごとに残を持ち、古い付与から消化する」形に広げられる。

## 7. まだ持っていない項目

移行の対象外だが、いずれ要ると見ているもの。

| 項目 | なぜ要るか | 大きさ |
|---|---|---|
| 希望休の受付簿 | 誰がいつ希望したかの記録場所が無い。いまは表に直接打つだけで、締切管理ができない | 小（シート1枚） |
| 同時出勤の禁止／必須の組 | 「この2人は同じ日に固めたい／避けたい」 | 中（エンジンに制約が増える） |
| 契約パターンマスタ | 社員マスタの `週勤務日数` `月間休日数` `連続出勤上限` `出られる曜日` の組に名前を付けたもの。社員は参照しつつ個別に上書き | 小（社員マスタに参照列を1本足すだけ） |
| 生成結果の理由 | 「週4を満たせなかったのは出られる曜日が3日しかないから」まで出せると手直しが早い | 中 |

## 移行の手順

1. 画面の**データ書き出し**タブで JSON を取り出す。
2. `Schema.gs` に上表の**新規**列を足す（`CFG_MEMBER` の J〜P、`PATTERN_MASTER` の G、`有休管理` シート）。
3. JSON を各シートへ流し込む取り込み口を作る。
4. `ShiftAuto.gs` の `readMembers_()` を新しい列まで読むよう広げる。
5. `Engine.gs` が新しい制約（連続出勤上限・出られる曜日・使える記号・締め作業）を見るようにする。

**2 と 3 は 4・5 と独立して進められる。** 先にシートの形だけ確定させれば、
エンジン側の実装と並行できる。
