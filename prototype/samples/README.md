# テスト用データ

`prototype/ShiftGrid.html` の**データ書き出し**タブに貼り、
「貼り付けた内容を取り込む」で入ります。**含まれているマスタだけ**が入れ替わるので、
社員だけ・医師だけの差し替えができます。

**氏名はすべて架空です。** 実在の職員・医師は書きません（Tier 3）。

---

## 社員マスタ（`staff` と `leave` を差し替え）

社員を入れ替えるとシフト表の入力は消えます（セルのキーが社員IDのため）。

| ファイル | 構成 | 何を試すもの |
|---|---|---|
| `staff-standard.json` | 13名（自動11／手動2） | 標準構成。まず素直に組めるか |
| `staff-short.json` | 8名（自動6／手動2） | **人手不足**。曜日下限を割る日が出る（10月で10日、11月で7日） |
| `staff-strict-run.json` | 11名（全員自動） | **連勤上限が全員3日**。入れ替えが働き公休が崩れないか |
| `staff-parttime.json` | 9名（自動8／手動1） | **週3〜4が多い**。公休枠を超える休みが空欄で出る |
| `staff-turnover.json` | 9名（自動8／手動1） | **在籍期間**。10月末で薬剤師E退職、11月から薬剤師F入職 |
| `setup-onsite.json` | 11名（自動9／手動2） | **現場の構成に近い形**。曜日別下限と連勤上限3日まで含む。下の節を参照 |

`staff-turnover.json` は月を切り替えると行が入れ替わります。

```
2026年10月: 薬剤師 A B C D E  派遣 1  事務 A B
2026年11月: 薬剤師 A B C D F  派遣 1  事務 A B
```

派遣は `rule: "手動"` なので自動配置の対象外です。頭数には入りますが、
記号は人が置きます（`canClose: false` ＝ 締め作業ができない）。

### `setup-onsite.json` について

実際に使われている構成と数値を写したものです（**氏名は伏せてあります**）。
社員マスタだけでなく、**店舗営業マスタと自動生成ルールも一緒に差し替えます**。

| 項目 | 値 |
|---|---|
| 薬剤師 | 7名（うち1名は日・水・木が出られず締め作業不可、1名は週4） |
| 派遣 | 2名（手動配置。1名は遅番のみ） |
| 事務 | 2名 |
| 連続出勤の上限 | 全員3日 |
| 曜日別の薬剤師 下限 | 日2 月6 火5 水3 木5 金6 土3 |

これを入れて自動生成すると、こうなります。

```
2026年10月  公休 全員 10/10（ビタビタ）  記号未定 5日  下限割れ 6日
2026年11月  公休 全員 11/11（ビタビタ）  記号未定 3日  下限割れ 6日
```

**下限割れは配置の不備ではなく人員の問題です。** 曜日別下限の合計（週30人日）に対して、
自動配置できる薬剤師6名＋週4が1名では供給が届きません。特に木曜が薄くなります
（月・金の6人を確保するため）。対処は次のいずれかです。

1. 派遣2名（手動）を薄い日に充てる — いまは自動配置の対象外なので、置けば埋まります
2. 木曜の下限を下げる
3. 月・金の下限を下げて木曜へ回す

## 医師の出勤表（`shift` の `doc1`〜`doc5` を差し替え）

医師名欄だけが入れ替わり、**スタッフのシフトは残ります**。すべて 2026年10月。

現場の実態を基本形にしてある。

```
月火金 … 5診 が多い     日 … 3診（確定）     その他 … 4診 の場合がある
```

| ファイル | 日 月 火 水 木 金 土 | 何を試すもの |
|---|---|---|
| `doctor-01-standard` | 3 5 5 4 4 5 4 | **標準**。いちばんよくある形 |
| `doctor-02-busy` | 3 5 5 5 5 5 4 | **混雑**。平日すべて5診（5診の日が21日） |
| `doctor-03-light` | 2 4 4 3 3 4 3 | **閑散**。全体に1診少ない。人が余る側 |
| `doctor-04-valley` | 3 5 5 3 3 5 4 | **中日が薄い**。週の真ん中が谷 |
| `doctor-05-late-week` | 3 4 4 4 5 5 5 | **週後半厚め**。木金土に寄せたときの連勤 |
| `doctor-06-sat-heavy` | 3 5 5 4 4 5 5 | **土曜厚め**。休日診療に人を回せるか |
| `doctor-07-holiday-closed` | 3 5 5 4 4 5 4 | **祝日は休診**（医師0）。薬局は開くので曜日下限だけで置く |
| `doctor-08-holiday-open` | 3 5 5 4 4 5 4 | **祝日も通常どおり**の診療数 |
| `doctor-09-rotating` | 3 5 5 4 4 5 4 | **隔週で顔ぶれが替わる**。診療数は標準のまま |
| `doctor-10-variable` | 3 5 5 4 4 5 4 | **週ごとに変動**（下側に振れる）。読みにくい月 |

**医師名欄は5行なので、6診以上は表に入りません。** 生成側でも検査していて、
超えると止まります。

### 現場構成（`setup-onsite`）と組み合わせた実測

```
  医師パターン              延べ出勤  下限割れ  上限超え  記号未定
  doctor-01-standard         141人日      6日      0日     66日
  doctor-02-busy             142人日      7日      0日     65日
  doctor-03-light            142人日      6日      1日     65日
  doctor-04-valley           142人日      3日      0日     65日
  doctor-05-late-week        142人日      8日      0日     65日
  doctor-06-sat-heavy        142人日      8日      0日     65日
  doctor-07-holiday-closed   141人日      6日      0日     66日
  doctor-10-variable         142人日      6日      0日     65日
```

**延べ出勤はどのパターンでもほぼ同じ（141〜142人日）。** 公休ノルマで
総量が決まるので、医師数が変わっても働ける総量は動かない。動くのは
**どの日に足りないか**だけ。

- `doctor-04-valley`（中日が薄い）が**いちばん収まりがよい**（下限割れ3日）
- `doctor-05-late-week` `doctor-06-sat-heavy` が**いちばん厳しい**（8日）。
  週後半・土曜に寄せると、いまの人員では届かない
- `doctor-03-light` は**上限超えが1日**出る。人が余る側の挙動が見える

`doctors.json` は医師マスタ（名前の一覧）で、出勤表とは別物です。

## 組み合わせの例

1. `staff-short.json` を入れる → 人手不足の状態にする
2. `doctor-shift-2026-11-busy.json` を入れる → 2026年11月の混雑月にする
3. 自動生成 → **過不足が大きくマイナスに振れる**のを確認する

## 作り直しと検証

```
node prototype/tools/make-samples.js     # このフォルダの JSON を作り直す

node prototype/tests/placement.test.js   # 既定のマスタで4か月ぶん検証する
node prototype/tests/samples.test.js     # 全パターンを配置に通して整合を見る
node prototype/tests/mustdow.test.js     # 「必ず出る曜日」が全ルールで守られるか
node prototype/tests/seam.test.js        # 月をまたぐ週で週上限を超えないか
node prototype/tests/manual.test.js      # 手で入れたものが自動生成で消えないか
node prototype/tests/history.test.js     # 編集履歴（戻す・進める・保存できない環境）
node prototype/tests/render.test.js      # 組み立て時にセルの中身が書けているか
```

`manual.test.js` は環境変数でマスタを差し替えられる。

```
FIXTURE=setup-onsite.json node prototype/tests/manual.test.js
```

`samples.test.js` は各パターンについて次を検査します。

- **公休（公休＋希望休）がノルマちょうど**か
- 連続出勤が個人の上限を超えていないか
- 週ごとの出勤が週勤務日数を超えていないか

あわせて「記号未定（公休枠を超えて空欄にした日）」と「曜日下限を割った日」の数を出します。
これは違反ではなく、**人が判断する必要がある箇所の数**です。

直近の結果:

| パターン | 月 | ノルマ | 記号未定 | 下限割れ |
|---|---|---|---|---|
| staff-standard | 2026/10 | 10 | 2 日 | 0 日 |
| staff-short | 2026/10 | 10 | 0 日 | **10 日** |
| staff-strict-run | 2026/10 | 10 | 0 日 | 0 日 |
| staff-parttime | 2026/10 | 10 | 4 日 | 5 日 |
| staff-turnover | 2026/10 | 10 | 0 日 | 4 日 |
| setup-onsite | 2026/10 | 10 | 3 日 | **6 日** |

**公休ノルマを見るのは `通常` の人だけ。** `固定曜日` と `週N日` は出勤日が
先に決まっているので、ノルマを当てると必ず矛盾する（VBA 版と同じ）。
この分離を入れる前は、パート中心のパターンで記号未定が 23 日出ていた。

全パターンで公休はノルマちょうど、連勤上限と週上限も満たしています。
